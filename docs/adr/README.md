# Architecture Decision Records (ADR)

Каталог фиксирует **обоснование** каждого алгоритма и технического решения
ядра `AE::mind_v1.1_Stable`. ADR отвечает не на вопрос «что делает код»
(это описано в [../README.md](../README.md) и [../TRAINING.md](../TRAINING.md)),
а на вопросы «почему выбрано именно так», «какие альтернативы отклонены» и
«какую цену мы за это платим».

## Формат записи

Каждый ADR содержит обязательные разделы:

- **Статус** — `Accepted`, `Superseded by ADR-XXXX`, `Deprecated`.
- **Контекст** — ограничения, которые вынудили принять решение.
- **Решение** — что именно зафиксировано в коде.
- **Обоснование** — почему это решение лучше альтернатив.
- **Последствия** — выигрыш, цена, риски и границы применимости.
- **Ссылки** — исходники, тесты и измерения; пути оформляются
  markdown-ссылками относительно `docs/adr/`, без жёстких якорей `#L<строка>`.
  Точные строки в коде печатает grep-скрипт [`find.sh`](find.sh).

Связь между решением и кодом двусторонняя: в шапке каждого модуля
указан конкретный ADR (`// ADR: docs/adr/NNNN-....md`), а у ключевых функций
и структур стоит локальная ссылка `// ADR-NNNN: docs/adr/NNNN-....md`.
Именно эти маркеры ищет скрипт, поэтому номера строк в ADR не хранятся и
не устаревают при сдвиге кода:

```bash
docs/adr/find.sh 0002     # где реализован ADR-0002
docs/adr/find.sh all      # карта всех ADR
docs/adr/find.sh --check  # проверить, что ADR и код ссылаются друг на друга
```

При переносе или переименовании файла достаточно обновить маркер в коде:
раздел «Ссылки» ADR ведёт на файл, а точную строку всегда показывает скрипт.
Проверка `make adr-check` (или `docs/adr/find.sh --check`) завершается с
ошибкой, если у ADR нет маркеров в коде или в коде есть неизвестный ADR.

Новая запись добавляется файлом `NNNN-kebab-case-title.md` и строкой в
таблицу ниже. Нумерация не переиспользуется. Изменение уже принятого решения
оформляется новым ADR со статусом `Superseded by`, а старый помечается
`Superseded`.

## Сквозные инварианты проекта

Эти принципы повторяются в нескольких ADR и считаются архитектурными
ограничениями, а не деталями реализации:

1. **Детерминизм.** Одинаковый вход даёт побитово одинаковый выход: фиксированные
   seed'ы, отсутствие wall-clock времени в признаках, детерминированные обходы.
2. **Алгоритмы — источник истины.** Нейросетевой контур обучается на выходе
   алгоритмов и не заменяет их; проверка результата остаётся алгоритмической.
3. **Один источник топологии.** Граф мыслей и поток Диница строятся из одного
   списка рёбер, поэтому AST не может сослаться на путь, которого нет.
4. **Ограниченная память и отсутствие аллокаций в горячем пути.** Плоские
   массивы, `mmap`-арены и фиксированные ёмкости вместо динамических структур.
5. **FFI-стабильность.** Публичная граница — чистый C ABI; C++-заголовки
   остаются деталью реализации.
