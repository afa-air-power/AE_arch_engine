# ADR-0008. Естественно-языковой вывод с обратным разбором

- **Статус:** Accepted
- **Дата:** 2026-11-19
- **Модуль:** 6.1, [include/natural_language_output.hpp](../../include/natural_language_output.hpp)

## Контекст

Выход ядра должен быть не только числом и AST, но и коротким ответом на
языке запроса. При этом нельзя допустить, чтобы вербализация добавила
смысл, которого не было в морфемной маске, или потеряла подтверждённые
домены. Нужен **замкнутый контур** «интент → текст → парсер → проверка»,
работающий детерминированно и без внешней модели.

## Решение

1. Из ожидаемой маски берутся биты семантических кластеров `[28..47]`
   (`CLUSTER_WINDOW`). Служебные типы `[24..27]` и кластер `MORPH` (бит 48)
   в сверке не участвуют, чтобы окончания не считались потерей смысла.
2. Домены, подтверждённые маской, сортируются по силе интента
   (`stable_sort` по `intent[a] > intent[b]`), затем по индексу домена.
3. `render_text` строит ответ из двух частей:
   - «Тема: …» — перечисление доменов (`граф`, `знание`, `поток`, …);
   - «Уточнение: …» — до двух определений вида «граф — это структура»;
   - в конце `max_flow/bottleneck` (только цифры, без морфем).
   Второе слово определения взято из того же кластера, поэтому предикат не
   добавляет новых доменов.
4. `parse_back` возвращает сгенерированный текст **в тот же парсер**
   (`lang::select_parser(text)->parse(text)`) и в морфемный trie.
5. Считаются `cluster_recall` и `cluster_precision` по битам кластеров.
6. Контур перебирает префиксы доменов: начинает с `min(3, present.size())`
   и добавляет недостающие, пока `recall < 0.999` или домены не кончились.
   Выбирается лучший вариант по `recall + precision`.
7. Порог сходимости: `recall ≥ 0.99` и `precision ≥ 0.8`.

## Обоснование

- **Почему обратный разбор тем же парсером.** Это единственный способ
  проверить, что текст действительно содержит нужные морфемы, а не просто
  «выглядит правильным». Круг замкнут: генератор и верификатор используют
  один словарь.
- **Почему определения из того же кластера.** Иначе определение добавило бы
  новый домен и снизило precision. Ограничение «второе слово из того же
  кластера» делает текст богаче, не размывая маску.
- **Почему сортировка по интенту.** Интент-вектор — единственный сигнал
  силы домена. Сортировка делает ответ осмысленным («главное — первым»),
  не добавляя новых сущностей.
- **Почему перебор префиксов, а не генерация с нуля.** Список доменов
  конечен (20), и добавление домена монотонно улучшает recall. Перебор
  ограничен и детерминирован; никакой случайности или модели.
- **Почему порог precision ниже recall.** Потеря смысла опаснее, чем
  лишний домен: `recall ≥ 0.99` обязательно, `precision ≥ 0.8` допускает
  небольшое разбавление. Это согласуется с приоритетом «не потерять
  подтверждённое».
- **Почему числа в конце.** `max_flow/bottleneck` — проверяемые величины;
  они не должны участвовать в морфемной сверке и не должны случайно
  совпасть с корнем.

## Последствия

- **Выигрыш:** ответ объясним, детерминирован и проверяем; отчёт содержит
  текст, recall, precision, число морфем и проходов; SLM-мост использует
  `nl_text` как основной `verbalized_response`.
- **Цена:** словарь доменов фиксирован (20 лексем); расширение предметных
  областей требует синхронного обновления `kDomainLexemes` и trie.
- **Ограничение:** это шаблонная вербализация, а не свободный текст. Она
  решает задачу «объяснить подтверждённые домены», а не «сгенерировать
  рассуждение».
- **Ограничение:** `recall/precision` считаются по битам кластеров, а не по
  полной семантике; служебные морфемы намеренно исключены.

Пример для `нейроны графа знаний и поток данных`:

```text
text:      Тема: нейрон, граф, поток и знание. 249/120
recall=1.00 precision=1.00 morphemes=12 passes=1 consistent=true
```
