# ADR-0007. Верифицированный AST-промпт как контракт с локальной SLM

- **Статус:** Accepted
- **Дата:** 2026-11-19
- **Модуль:** 6, `include/time_ray_ast.hpp` (`compile_verified_ast_prompt`)

## Контекст

Локальная SLM (1.5B–3B) склонна добавлять факты, которых нет во входных
данных. Нужен формат промпта, который:

- передаёт модели только проверенные узлы и числа;
- явно запрещает внешние факты;
- содержит трассируемую ссылку на узел/чанк знаний;
- остаётся компактным (важен размер контекста SLM);
- может быть проверен программно (контрактные тесты).

## Решение

Промпт — S-выражение `AE_VERIFIED_AST_V1.1` со строгой схемой:

```text
(AE_VERIFIED_AST_V1.1
  (META :engine "AE::mind_v1.1_Stable" :hallucination_guard "STRICT_BOOLEAN_MASK"
        :target_slm "Local-SLM-3B-Instruct" :centroid_cluster_id ... :centroid_hops ...)
  (QUERY_INTENT :raw "..." :morpheme_mask "0x..." :dinitz_max_flow ...)
  (THOUGHT_GRAPH_TOPOLOGY :root ... :nodes ... :spanning_mechanism "KRUSKAL_DSU_BINUP_LCA"
    (THOUGHT_NODE :step ... :node_id ... :parent_id ... :depth ...
                  :edge_weight ... :lca_with_root ... :path_max_weight ...
                  :fact_ref "KB_CHUNK_...")
    ...)
  (SLM_DIRECTIVE :mode "DETERMINISTIC_VERBALIZATION"
                 :instruction "Сформируй точный научно-технический ответ строго
                               по узлам THOUGHT_NODE без добавления внешних фактов."))
```

Каждый `THOUGHT_NODE` берётся из `optimal_path` — пути в остовном дереве, а
не из эвристики потока. `estimated_tokens = len(ast_text) / 4 + 35`.
`explainable_trace` — короткая цепочка
`Intent → MorphemeMask → Centroid → ThoughtGraph → DinitzFlow → AST`.

## Обоснование

- **Почему S-выражение, а не JSON.** S-выражение:
  - компактнее (меньше кавычек и запятых) при том же числе полей;
  - естественно читается как дерево и легко парсится регулярными тестами;
  - допускает вложенные узлы без массивов.
  JSON был бы удобнее для сторонних инструментов, но дороже по токенам.
- **Почему только проверенные узлы.** Каждый `THOUGHT_NODE` уже существует в
  топологии, имеет `parent_id`, `depth`, вес и ссылку `fact_ref`. Модель не
  получает свободного контекста, к которому можно «приклеить» галлюцинацию.
- **Почему `STRICT_BOOLEAN_MASK` в META.** Это явный маркер для SLM и для
  логов: ответ ограничен битами морфемной маски. Проверяется тестом
  `ast_contract`.
- **Почему `fact_ref` формируется как `centroid_id * 100 + u`.** Это
  детерминированная, дешёвая и проверяемая ссылка на чанк знаний. Реальный
  RAG может заменить формулу, не меняя схему промпта.
- **Почему `path_max_weight`, а не bottleneck.** AST печатает верхнюю оценку
  веса пути; истинный bottleneck доступен отдельно (`path_bottleneck` в
  метриках и NL-ответе). Так AST не обещает больше, чем даёт поток, и
  сохраняет различие двух величин.
- **Почему оценка токенов делением на 4.** Это консервативная эвристика для
  английского/кода; для русского она завышает оценку, что безопаснее
  (контекст не переполнится).

## Последствия

- **Выигрыш:** промпт объясним, воспроизводим и проверяем; задержка
  компиляции AST не входит в `latency_us` ядра; SLM получает только
  подтверждённые узлы.
- **Цена:** формат завязан на `AE_VERIFIED_AST_V1.1`; изменение схемы —
  это новый ADR и обновление тестов/парсеров.
- **Ограничение:** S-выражение не является стандартом; сторонние
  инструменты должны знать схему. Для интеграций предусмотрен
  `ae_engine_get_last_ast` и `trace`.
- **Ограничение:** `estimated_tokens` — оценка, а не токенизация реального
  токенизатора SLM.
