# ADR-0002. Морфемный Patricia trie и 64-битная маска сочетаемости

- **Статус:** Accepted
- **Дата:** 2026-11-19
- **Модуль:** 3.2, `include/morphemic_trie.hpp`

## Контекст

Нужен детерминированный, объяснимый и дешёвый способ извлечь из текста
семантические домены и типы морфем, не используя внешние словари, токенизаторы
и ML-модели. Результат должен:

- работать для русского и английского в одном пространстве признаков;
- быть упакован в одно машинное слово, чтобы маску можно было передавать через
  C ABI и использовать как гейт для потока;
- допускать динамическую регистрацию морфем из Python/Rust/Go без перетирания
  встроенного инвентаря;
- не давать ложных срабатываний на словах вне словаря.

## Решение

Взят **Patricia trie** (сжатый префиксный бор): узлы хранят метку ребра
целиком, а не один символ, поэтому 1804 морфемы укладываются в 2580 узлов.
Инвентарь состоит из 1028 русских и 776 английских морфем: приставки, корни
20 семантических кластеров, суффиксы и окончания.

Маска `uint64_t` разделена на поля:

```text
[ 0.. 7]  базовые домены смысла (semantic_tag 0..7 Диница, всегда активны)
[ 8..15]  домены, гейтируемые декодером по tag 8..15
[16..23]  интент-биты Taylor-Intent Kernel
[24..27]  тип морфемы: PREFIX / ROOT / SUFFIX / INFLECTION
[28..47]  семантический кластер корня (20 кластеров)
[48..63]  свободно для динамической регистрации
```

Идентификаторы `0..255` зарезервированы под `ae_engine_add_morpheme` и FFI,
встроенный инвентарь начинается с `FIRST_BUILTIN_ID = 256`.

Разбор `compile_morpheme_mask` идёт **пословно жадным longest-match**:
внутри слова выбирается самая длинная зарегистрированная морфема, разбор
продолжается с её конца; неизвестный участок обрывает цепочку слова.

## Обоснование

- **Почему Patricia trie, а не хеш-таблица или суффиксный автомат.**
  Нужен поиск «самого длинного префикса из словаря» на каждом шаге слова.
  Хеш-таблица проверяет только точные строки и требует перебора длин, а
  суффиксный автомат избыточен и хуже кэшируется. Сжатый бор даёт
  `O(длина слова)` с малым числом узлов и без аллокаций на поиск.
- **Почему одно 64-битное слово, а не структура.** Маска передаётся через C
  ABI, сравнивается побитово, попадает в признаки как `popcount` и напрямую
  гейтирует рёбра Диница (`apply_boolean_mask_and_reset`). Одно слово
  исключает сериализацию и рассинхронизацию полей.
- **Почему longest-match и непрерывная цепочка.** Без непрерывности слово
  `кот` дало бы приставку `от`, а поиск вложенных совпадений завысил бы
  `matched_morphemes` (например, `аст` внутри `астро`). Жадный longest-match
  даёт стабильный, объяснимый разбор.
- **Почему кластеры корней, а не эмбеддинги.** Кластер — это бит, который
  можно проверить, напечатать и объяснить. 20 кластеров покрывают предметные
  области проекта (графы, знание, поток, текст, вычисления и т.д.) и не
  требуют обученного словаря.
- **Почему зарезервированы `0..255`.** Динамическая регистрация из FFI должна
  быть безопасной: пользовательский `id` не должен перетирать встроенную
  морфему.

## Последствия

- **Выигрыш:** `compile_morpheme_mask` для 1804 морфем занимает ~330 ns
  (~3.0 млн запросов/с); разбор детерминирован; словарь расширяется без
  пересборки ядра.
- **Цена:** словарь покрывает только зарегистрированные основы. Неизвестное
  слово не даёт кластеров — это осознанный выбор в пользу точности
  (см. тест `trie_unknown_words_clean`), а не попытка угадать смысл.
- **Ограничение:** маска описывает наличие домена, а не его роль или вес.
  Порядок и сила домена восстанавливаются по интент-вектору в NL-модуле.
- **Риск:** ручной инвентарь требует сопровождения при расширении предметных
  областей; для новых доменов нужно добавлять биты через ADR/расширение
  раскладки.
