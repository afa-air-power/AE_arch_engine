# ADR-0001. Taylor-Intent Kernel: полиномиальный forward вместо трансцендентных функций

- **Статус:** Accepted
- **Дата:** 2026-11-19
- **Модуль:** 3.1, `include/taylor_intent_kernel.hpp`

## Контекст

Ядру нужен быстрый детерминированный преобразователь запроса в 16-мерный
интент-вектор. Вектор используется двумя потребителями:

1. как биты `[16..23]` морфемной маски (`intent[b] > -0.25`);
2. как признаки `[0..15]` обучаемой модели.

Требования: предсказуемая задержка на CPU без GPU, отсутствие аллокаций в
горячем пути, воспроизводимость при фиксированном seed'е и достаточная
нелинейность, чтобы вектор не был линейной функцией байтов запроса.

## Решение

Зафиксирована двухслойная сеть `32 → 150 → 16` с весами, инициализированными
`std::mt19937(42)` и нормальным распределением (`σ=0.15` для `W1`, `σ=0.10`
для `W2`), и двумя режимами активации:

- `forward_taylor` — полиномиальные приближения:
  - `taylor_tanh(x) = x·(1 − x²·(1/3 − 2/15·x²))` — ряд Тейлора 5-го порядка,
    с насыщением до `±0.905148` при `|x| > 1.5`;
  - `taylor_gelu(x)` — GELU через `tanh`-приближение с коэффициентами
    `√(2/π) = 0.79788456` и `0.044715`, где `tanh` тоже полиномиальный;
- `forward_transcendental` — эталонная реализация с `std::tanh`, нужная
  только для сравнения и тестов.

Все матрицы выровнены по 64 байта (`alignas(64)`), промежуточный слой хранится
на стеке в `std::array`, динамических аллокаций нет.

## Обоснование

- **Почему полином, а не `std::tanh`.** `std::tanh` на типичном x86 — это
  библиотечный вызов с ветвлениями и высокой латентностью. Ряд Тейлора 5-го
  порядка на интервале `[-1.5, 1.5]` даёт достаточную точность для
  булева порога `-0.25` и для нормированных признаков, но выполняется как
  несколько умножений и сложений, векторизуемых компилятором.
- **Почему насыщение на `1.5`.** За пределами `1.5` ряд расходится, а
  настоящий `tanh` уже практически насыщен. Замена значением
  `tanh(1.5) = 0.905148` сохраняет монотонность и убирает выбросы без
  ветвления в горячем цикле.
- **Почему GELU, а не ReLU.** GELU даёт гладкий выход и лучше переносит
  малое число нейронов; для 150 скрытых единиц это снижает «мёртвые» нейроны.
- **Почему фиксированный seed.** Интент-вектор входит в маску и в признаки;
  случайная инициализация при каждом старте ломала бы воспроизводимость
  бенчмарков и тестов.

Измерения (`build/ae_bench`, Release, `-O3 -march=native`):

| Операция | p50 | Пропускная способность |
|---|---:|---:|
| `forward_taylor` | 3.85 µs | ~260 тыс. вызовов/с |
| `forward_transcendental` | 6.80 µs | ~147 тыс. вызовов/с |
| Ускорение | **1.77×** | — |

## Последствия

- **Выигрыш:** задержка ядра не зависит от качества libm; полином
  детерминирован на разных платформах; режим сравнения остаётся в коде и
  позволяет измерять деградацию.
- **Цена:** приближение не является математически точным `tanh`; за
  пределами `1.5` теряется различие между большими значениями. Для пороговой
  логики и нормированных признаков это приемлемо, для задач, где нужна
  точная гладкая функция, использовать `forward_transcendental`.
- **Граница применимости:** это не обученная модель. Веса фиксированы, вектор
  кодирует идентичность/статистику запроса, а не семантику. Именно поэтому
  `intent`-признаки по умолчанию исключены из обучения на малом корпусе
  (см. [ADR-0012](0012-trainable-graph-contour.md)).
