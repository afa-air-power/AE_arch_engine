# ADR-0012. Обучаемый контур на признаках алгоритмов

- **Статус:** Accepted
- **Дата:** 2026-11-19
- **Модули:** [include/algorithm_features.hpp](../../include/algorithm_features.hpp), [training/ae_features.py](../../training/ae_features.py), [training/ae_graph_train.py](../../training/ae_graph_train.py), [training/ae_graph_hip.py](../../training/ae_graph_hip.py)
  `training/ae_graph_train.py`, `training/ae_graph_hip.py`

## Контекст

Нужно добавить обучаемую модель, не превращая ядро в чёрный ящик. Ограничения:

- алгоритмы должны оставаться проверяемыми и объяснимыми;
- признаки должны быть детерминированными и воспроизводимыми;
- обучение должно работать на CPU без обязательного PyTorch/ROCm;
- на малом корпусе модель не должна запоминать запросы вместо обобщения;
- оценка качества должна быть устойчивой при малом `N`.

## Решение

**Признаки.** 118-мерный вектор `AlgorithmFeatureVector` в `[0, 1]`,
собранный из выходов уже работающих модулей:

```text
[ 0..15] intent Taylor-Intent Kernel
[16..24] морфемная маска и словарь trie
[25..27] центроидная декомпозиция Mega RAG
[28..31] поток Диница и bottleneck
[32..41] топология графа мыслей (путь, LCA-веса, степени)
[42..45] Time-Ray (forward/backward/anomalies/средний вес)
[46..50] обратный разбор NL (recall/precision/passes)
[51..55] метаданные запроса и плотность морфем
[56..75] индикаторы 20 семантических кластеров
[76..95] поддержка кластеров: log1p(число морфем) / log1p(16)
```

Поддержка считается в `MorphemeAnalysis`: для каждой морфемы, попавшей в
разбор, увеличиваются счётчики всех кластеров из её маски сочетаемости.
Индикатор отвечает «тема встретилась», счётчик — «насколько сильно».

Дополнительно trie строит детерминированное дерево предложения. Пунктуация и
союзы разделяют запрос на чанки, в каждом чанке выделяется голова и её
зависимые слова. Поддержка кластеров агрегируется на уровне поддеревьев.
Составные термины (`neural network → MIND`, `network topology → GRAPH`,
`network flow → FLOW`, `routing table → NET`, `таблица маршрутов → NET`)
передают поддержку кластеру головы. Это сохраняет локальный контекст и не
сводит всё предложение к мешку независимых слов.

В признаки **не входит wall-clock время**: вместо него используется средний
вес ребра пути, поэтому одинаковый запрос даёт побитово одинаковый вектор.

**Группы.** `training/ae_features.py` делит вектор на группы `intent`,
`morphology`, `centroid`, `flow`, `topology`, `timeray`, `nl`, `query`,
`clusters`, `cluster_counts`. По умолчанию исключены `intent`, `centroid`,
`timeray`, потому что они выводятся из байтового хэша запроса и кодируют
идентичность, а не смысл. Текущий default — 28 признаков:
`cluster_core` (9 битов) + `cluster_counts_core` (9 счётчиков) +
`chunk_core` (9 локальных максимумов) + `sentence` (глубина дерева).
Группа `rdt` содержит 3 дополнительных признака структурных поворотов и
включается отдельно для графового режима.

**Модель.** `GraphSAGEClassifier` — двухслойный mean-aggregation
классификатор с явным backward pass на NumPy:

- `h0 = Â·X`, `z1 = h0·W1 + b1`, `h1 = ReLU(z1)`, `h2 = Â·h1`,
  `logits = h2·W2 + b2`;
- `Â = D^{-1/2}(A + I)D^{-1/2}`;
- при `"graph": "none"` adjacency пуст, `Â` не строится, агрегация —
  тождественная (`h0 = X`, `h2 = h1`); это экономит плотную `N×N` матрицу;
- стандартизация по train split;
- Adam (`β1=0.9`, `β2=0.999`, `ε=1e-8`), L2;
- early stopping по validation macro-F1 с восстановлением лучшей эпохи;
- `--hidden-dim 0` — линейный режим, устойчивее на малых корпусах;
- стратифицированная k-fold кросс-валидация с внутренним validation.

**Граф над образцами.** `--graph none|lexical|knn`; по умолчанию `none`,
потому что на текстовом корпусе `lexical` и `knn` смешивают темы и ухудшают
метрику. Пустой граф кодируется нулевой матрицей `0×0`, а не плотной `N×N`.

**Корпус.** Ручной якорь (450 запросов) остаётся единственной честной
оценкой: `val`/`test` никогда не пополняются синтетикой. Синтетическая волна
(4 500 запросов, 500 на класс, 250 RU / 250 EN) целиком лежит в `train` и
валидируется через `compile_morpheme_analysis`: метка принимается только
если целевой кластер присутствует в trie-разборе.

## Обоснование

- **Почему признаки, а не end-to-end модель.** Ядро должно оставаться
  проверяемым: каждое число в векторе можно объяснить конкретным алгоритмом.
  Модель учится на выходах алгоритмов и не может «отменить» их решение.
- **Почему NumPy, а не PyTorch.** Контракт данных и CPU-эталон должны
  работать на машинах без ROCm/PyTorch. NumPy-реализация детерминирована,
  мала и служит reference-реализацией для будущего GPU-backend.
- **Почему исключены identity-группы.** `intent`, `centroid`, `timeray`
  зависят от байтового хэша запроса. На малых корпусах они дают запоминание
  вместо обобщения; поэтому default ограничен 18 смысловыми признаками
  (9 профильных битов + 9 счётчиков).
- **Почему счётчики кластеров.** Маска trie хранит только факт наличия
  кластера, поэтому `graph coloring` и `graph spectrum` неразличимы. Счётчик
  поддержки возвращает эту информацию без новых эвристик в Python: он
  считается в том же C++-проходе, что и маска.
- **Почему синтетика только в train.** Ручной `val`/`test` — независимый
  якорь. Если добавить синтетику в held-out, метрика перестанет измерять
  обобщение на живые формулировки и начнёт измерять генератор.

- **Почему GraphSAGE-подобная агрегация.** Она использует граф над
  образцами, если он есть, но не требует его: при `A = 0` остаётся
  линейный/MLP-режим. Это позволяет сравнивать режимы без смены кода.
- **Почему macro-F1, а не accuracy.** Классы могут быть несбалансированы;
  macro-F1 штрафует модель за «забытые» классы.
- **Почему стратифицированная CV.** Один test split из 18 образцов шумит;
  CV даёт среднее и разброс, по которым можно принимать решение.
- **Почему ранняя остановка по validation F1, а не по loss.** На малых
  корпусах validation loss растёт почти сразу, а F1 ещё держит полезную
  эпоху; checkpoint по лучшему F1 не фиксирует переобученную эпоху.

## Последствия

- **Выигрыш:** измеренные метрики seed-корпуса: hold-out accuracy `0.667`,
  macro-F1 `0.663`; 5-fold CV accuracy **0.856 ± 0.125**, macro-F1
  **0.844 ± 0.141**. На ручном якоре (450 запросов, 9 × 50) старый
  53-мерный default давал CV `0.813 ± 0.005`. После внедрения 18-мерного
  набора (биты + счётчики) CV на том же якоре — **0.868 ± 0.014**; после
  синтетической волны hold-out `val` + `test` (5 seed) — **0.898 ± 0.013**
  (`val` 0.864 ± 0.011, `test` 0.931 ± 0.023), однозначные —
  **0.944 ± 0.004**, трудные пары — **0.813 ± 0.042** (было `0.500`),
  RU — 0.849 ± 0.009, EN — 0.937 ± 0.021. 5-fold CV по полному корпусу
  4 950 — **0.968 ± 0.002**. Признаки детерминированы и проверяются тестом.
- **Цена:** синтетика улучшает регуляризацию, но не заменяет ручную волну:
  её распределение задано генератором. Слой составных терминов покрывает
  только известные конфликты (`neural network`, `routing table`,
  `network flow`); для неизвестных контекстов нужны синтаксические признаки
  (голова фразы, предлоги), а не бесконечное расширение таблицы. Ручной
  `val`/`test` остаётся главной оценкой.
- **Ограничение:** HIP-backend обучения не реализован; `ae_graph_hip.py` —
  smoke test устройства, а не ускоритель. Полный HIP-контур — отдельная
  задача.
- **Ограничение:** модель классифицирует запросы, а не генерирует ответ;
  генерация остаётся за детерминированным NL-модулем/SLM.
