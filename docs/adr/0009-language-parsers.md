# ADR-0009. Языковые парсеры: единый интерфейс и детерминированная морфология

- **Статус:** Accepted
- **Дата:** 2026-11-19
- **Модуль:** [include/lang/](../../include/lang/), [src/lang/](../../src/lang/), [src/lang_parser.cpp](../../src/lang_parser.cpp)

## Контекст

Ядру нужны разборы текста и кода, которые:

- возвращают морфемы для human-языков и дерево для программ;
- имеют один интерфейс, чтобы конвейер не зависел от конкретного языка;
- не тянут внешние NLP-библиотеки и модели;
- работают детерминированно и быстро;
- допускают расширение семействами (`SCIENCE`, `VERBAL`) без изменения
  потребителей.

## Решение

- `ae::lang::LanguageInterface` — общий интерфейс `parse`, `language`,
  `family`; `ParseResult` содержит `morphemes` и `MeaningNode meaning_tree`.
- `LanguageFamily` = `HUMAN`, `SCIENCE`, `VERBAL`, `PROGRAMMING`.
- Пространства имён `ae::lang::human`, `science`, `verbal`, `programing`
  дают доступ к одному интерфейсу.
- `detect_language` сравнивает число кириллических байтов (`0xD0`, `0xD1`)
  с числом латинских букв; при равенстве выбирается английский.
- `select_parser(text)` маршрутизирует RU/EN; `select_parser(family, text)`
  — по семейству. Для `SCIENCE`/`VERBAL` возвращается `nullptr`, пока нет
  реализации.
- Морфологический разбор (`include/lang/detail/parser_detail.hpp`):
  - слово = байты `>= 0x80`, `isalnum`, `'`;
  - longest-match приставки, не более `MAX_PREFIXES_PER_WORD = 2`;
  - остаток основы не короче `MIN_STEM_BYTES = 6` (три кириллических
    символа в UTF-8);
  - longest-match суффикс, оставляющий непустую основу;
  - позиции морфем — байтовые смещения `[begin, end)`.
- Программный парсер строит `MeaningNode` для документа, программы,
  функций, блоков, объявлений, управляющих конструкций и лексических узлов.

## Обоснование

- **Почему единый интерфейс.** Конвейер, NL-модуль и FFI не должны знать,
  какой парсер выбран. Полиморфизм через `LanguageInterface` позволяет
  добавить `SCIENCE`/`VERBAL` позже без изменения `AEEnginePipeline`.
- **Почему собственный морфологический разбор.** Внешние NLP-стеки
  (spaCy, pymorphy, Stanza) тянут модели, память и недетерминизм версий.
  Для задачи «найти подтверждённые домены» достаточно словаря аффиксов,
  который уже есть в trie.
- **Почему `MIN_STEM_BYTES = 6`.** Без словаря основ короткие остатки дают
  ложные разборы (`воин`, `изба`, `разум`). Три кириллических символа —
  минимальная основа, которую ещё можно считать осмысленной.
- **Почему `MAX_PREFIXES_PER_WORD = 2`.** Две приставки реальны
  (`пере-под-ключение`), три и более — почти всегда артефакт жадного
  разбора.
- **Почему исключены короткие приставки** (`ко-`, `во-`, `су-`, `ре-`,
  `ни-`, `де-`). Без словаря основ они разрушают частотные слова
  (`дерево`, `вопрос`, `компьютер`).
- **Почему `nullptr` для нереализованных семейств.** Явный отказ лучше
  тихой подмены парсера: вызывающий код обязан обработать отсутствие
  реализации, а не получить неверное дерево.

## Последствия

- **Выигрыш:** разбор RU ~9.45 µs на 22 слова, EN ~1.14 µs на 7 слов,
  програмный фрагмент ~2.04 µs; нет внешних зависимостей; позиции морфем
  пригодны для обратного разбора.
- **Цена:** словарный подход не покрывает морфологию продуктивно; неизвестные
  слова остаются одной основой без суффикса.
- **Ограничение:** `SCIENCE`/`VERBAL` пока не реализованы; `select_parser`
  возвращает `nullptr`. Это зафиксировано в тестах и документации.
- **Ограничение:** определение языка по байтам не различает смешанный текст;
  при равенстве выбирается английский — предсказуемое, но не идеальное
  поведение.
