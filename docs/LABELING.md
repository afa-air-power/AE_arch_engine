# Ручная разметка корпуса текстовых кластеров

Документ описывает, как пополнять размеченный корпус, который используется
для обучения и проверки классификатора тем. Разметка ведётся вручную и
хранится отдельно от сгенерированного seed-корпуса.

## Файлы

| Файл | Назначение | Кто изменяет |
|---|---|---|
| `training/corpora/text_clusters.json` | seed-корпус, 90 запросов | генерируется `tools/make_text_cluster_corpus.py`, вручную не редактируется |
| `training/corpora/text_clusters_manual.json` | ручная разметка, 180 запросов | человек |
| `training/corpora/text_clusters_expanded.json` | объединённый корпус, 270 запросов | генерируется `tools/merge_corpora.py` |
| `data/text_clusters_expanded_features.json` | признаки объединённого корпуса | генерируется `training.ae_features` |

Seed и ручной корпус не пересекаются: `merge_corpora.py` схлопывает
дубликаты и падает, если один и тот же запрос размечен разными метками.

## Классы

Порядок `labels` фиксирован и совпадает с `label` в каждом примере:

| label | cluster | Типичные маркеры |
|---:|---|---|
| 0 | `GRAPH` | граф, дерево, вершина, ребро, связность, обход, топология |
| 1 | `KNOW` | знание, смысл, факт, логика, онтология, контекст, память |
| 2 | `FLOW` | поток, процесс, конвейер, очередь, маршрут, этапы, задержка |
| 3 | `TEXT` | текст, токен, морфема, грамматика, синтаксис, корпус, перевод |
| 4 | `NUM` | число, матрица, вектор, полином, вероятность, интеграл, метрика |
| 5 | `COMPUTE` | программа, компилятор, процессор, кэш, модуль, сборка, ядро |
| 6 | `MIND` | мозг, нейрон, внимание, эмоция, решение, психология, инсайт |
| 7 | `NET` | сеть, протокол, пакет, сокет, маршрутизатор, трафик, сессия |
| 8 | `ACTION` | поиск, сортировка, фильтрация, генерация, импорт, миграция |

## Правила разметки

1. **Один доминирующий кластер.** Метка — главная тема запроса, а не все
   встретившиеся слова. `граф знаний` — это `GRAPH`, потому что запрос про
   граф; `база знаний и правила вывода` — `KNOW`.
2. **Не смешивать равноправные темы.** Если запрос одинаково про сеть и про
   поток, его лучше переформулировать или разбить на два примера. Смешанные
   примеры допустимы только как «трудные» и требуют комментария.
3. **Язык.** Русский и английский примеры равноценны; технические
   англицизмы в русском запросе допустимы (`кэш`, `протокол`, `байткод`).
4. **Уникальность.** Нормализованные дубликаты (регистр и пробелы не важны)
   запрещены. Повтор темы — да, повтор строки — нет.
5. **Баланс.** В первой волне на каждый класс приходится 12 `train`, 4 `val`,
   4 `test`. Для новых волн держите примерно 70/15/15 и проверяйте, что у
   каждого класса есть `train` и хотя бы один held-out пример.
6. **Провенанс.** Новые примеры помечаются `"source": "manual-v2"` (или
   другой версией), чтобы можно было отследить волну разметки.
7. **Не подгонять под модель.** Нельзя менять `val`/`test` после просмотра
   ошибок классификатора, кроме исправления объективно неоднозначной
   формулировки. Исправления фиксируются в комментарии/коммите.

## Формат примера

```json
{
  "query": "топология ориентированного графа и циклы",
  "label": 0,
  "cluster": "GRAPH",
  "split": "train",
  "source": "manual-v1"
}
```

`cluster` должен совпадать с `labels[label]`; `merge_corpora.py` проверяет
это и восстанавливает поле, если оно пропущено.

## Рабочий цикл

```bash
# 1. добавить примеры в text_clusters_manual.json

# 2. проверить схему и собрать объединённый корпус
python3 tests/test_corpus.py
python3 tools/merge_corpora.py \
  training/corpora/text_clusters.json \
  training/corpora/text_clusters_manual.json \
  -o training/corpora/text_clusters_expanded.json

# 3. извлечь признаки из алгоритмов ядра
python3 -m training.ae_features \
  training/corpora/text_clusters_expanded.json \
  data/text_clusters_expanded_features.json

# 4. обучить и оценить
python3 -m training.ae_graph_train data/text_clusters_expanded_features.json \
  --epochs 300 --hidden-dim 0 --learning-rate 0.01 --weight-decay 0.01 \
  --patience 60 --checkpoint checkpoints/text_clusters_expanded.json
python3 -m training.ae_graph_train data/text_clusters_expanded_features.json \
  --cv 5 --epochs 300 --hidden-dim 0 --learning-rate 0.01 --weight-decay 0.01
```

`tests/test_corpus.py` проверяет: диапазон меток, соответствие
`cluster`/`labels`, допустимые split'ы, отсутствие дубликатов, наличие
`train` и held-out примеров у каждого класса и актуальность объединённого
файла.

## Текущее состояние (волна manual-v1)

- 270 запросов: 9 классов × 30, из них 180 ручных и 90 seed;
- split: 162 `train` / 54 `val` / 54 `test`, по 18/6/6 на класс;
- feature groups: `morphology, flow, topology, nl, query, clusters`
  (53 признака, без hash-derived `intent/centroid/timeray`).

Метрики на объединённом корпусе (линейный режим, `hidden-dim 0`):

| Метрика | Seed (90) | Expanded (270) |
|---|---:|---:|
| Hold-out test accuracy | 0.667 (18) | **0.944** (54) |
| Hold-out test macro-F1 | 0.663 | **0.937** |
| 5-fold CV accuracy | 0.856 ± 0.125 | **0.863 ± 0.038** |
| 5-fold CV macro-F1 | 0.844 ± 0.141 | **0.858 ± 0.042** |

Цифры не сравнимы напрямую: у expanded другой, более разнообразный test
split. Важнее, что разброс CV уменьшился примерно в три раза, а hold-out
перестал быть шумным.

Оставшиеся ошибки hold-out — все в `GRAPH` и связаны с лексической
неоднозначностью (`connected components` даёт бит `NET`, `валентность`
пересекается с другими корнями). Это кандидаты на следующую волну: либо
более однозначные формулировки, либо явные «трудные» примеры с комментарием,
но не подмена метки ради метрики.

## Следующие шаги

1. Довести каждый класс до 50–100 примеров, сохраняя баланс и разнообразие
   формулировок (не шаблоны).
2. Добавить трудные пары (`GRAPH`/`NET`, `COMPUTE`/`ACTION`,
   `KNOW`/`TEXT`) с явным комментарием, почему выбрана метка.
3. Проверить согласованность разметки вторым проходом (inter-annotator
   agreement) на случайной подвыборке.
4. Пересчитать метрики и обновить таблицу; хранить отчёт в `reports/`
   (каталог не коммитится).
