# Ручная разметка корпуса текстовых кластеров

Документ описывает, как пополнять размеченный корпус, который используется
для обучения и проверки классификатора тем. Разметка ведётся вручную и
хранится отдельно от сгенерированного seed-корпуса.

## Файлы

| Файл | Назначение | Кто изменяет |
|---|---|---|
| `training/corpora/text_clusters.json` | seed-корпус, 90 запросов | генерируется `tools/make_text_cluster_corpus.py`, вручную не редактируется |
| `training/corpora/text_clusters_manual.json` | волна `manual-v1`, 180 запросов | человек |
| `training/corpora/text_clusters_manual_v2.json` | волна `manual-v2`, 180 запросов, 52 трудных примера | человек |
| `training/corpora/text_clusters_synthetic.json` | синтетическая волна, 4 500 запросов, только `train` | генерируется `tools/make_text_cluster_synthetic.py` |
| `training/corpora/text_clusters_expanded.json` | объединённый корпус, 4 950 запросов | генерируется `tools/merge_corpora.py` |
| `data/text_clusters_expanded_features.json` | признаки объединённого корпуса | генерируется `training.ae_features` |

Seed, ручной корпус и синтетика не пересекаются: `merge_corpora.py`
схлопывает дубликаты и падает, если один и тот же запрос размечен разными
метками.

## Классы

Порядок `labels` фиксирован и совпадает с `label` в каждом примере:

| label | cluster | Типичные маркеры |
|---:|---|---|
| 0 | `GRAPH` | граф, дерево, вершина, ребро, связность, обход, топология |
| 1 | `KNOW` | знание, смысл, факт, логика, онтология, контекст, память |
| 2 | `FLOW` | поток, процесс, конвейер, очередь, маршрут, этапы, задержка |
| 3 | `TEXT` | текст, токен, морфема, грамматика, синтаксис, корпус, перевод |
| 4 | `NUM` | число, матрица, вектор, полином, вероятность, интеграл, метрика |
| 5 | `COMPUTE` | программа, компилятор, процессор, кэш, модуль, сборка, ядро |
| 6 | `MIND` | мозг, нейрон, внимание, эмоция, решение, психология, инсайт |
| 7 | `NET` | сеть, протокол, пакет, сокет, маршрутизатор, трафик, сессия |
| 8 | `ACTION` | поиск, сортировка, фильтрация, генерация, импорт, миграция |

## Правила разметки

1. **Один доминирующий кластер.** Метка — главная тема запроса, а не все
   встретившиеся слова. `граф знаний` — это `GRAPH`, потому что запрос про
   граф; `база знаний и правила вывода` — `KNOW`.
2. **Не смешивать равноправные темы.** Если запрос одинаково про сеть и про
   поток, его лучше переформулировать или разбить на два примера. Смешанные
   примеры допустимы только как «трудные» и требуют комментария.
3. **Язык.** Русский и английский примеры равноценны; технические
   англицизмы в русском запросе допустимы (`кэш`, `протокол`, `байткод`).
4. **Уникальность.** Нормализованные дубликаты (регистр и пробелы не важны)
   запрещены. Повтор темы — да, повтор строки — нет.
5. **Баланс.** В каждой волне на каждый класс приходится 12 `train`,
   4 `val`, 4 `test` (20 примеров). Для новых волн держите примерно 70/15/15
   и проверяйте, что у каждого класса есть `train` и хотя бы один held-out
   пример.
6. **Трудные пары.** Примеры, где встречаются маркеры двух кластеров,
   помечаются полем `notes` с парой (`GRAPH/NET`, `COMPUTE/ACTION`,
   `KNOW/TEXT`, `FLOW/NET`, `MIND/NET`, `NUM/GRAPH`) и объяснением, почему
   выбрана метка. Они не считаются ошибкой разметки: именно на них
   проверяется устойчивость модели.
7. **Провенанс.** Новые примеры помечаются `"source": "manual-v2"` (или
   другой версией), чтобы можно было отследить волну разметки.
8. **Не подгонять под модель.** Нельзя менять `val`/`test` после просмотра
   ошибок классификатора, кроме исправления объективно неоднозначной
   формулировки. Исправления фиксируются в комментарии/коммите.

## Синтетическая волна

Синтетика — это регуляризация, а не замена ручной разметки:

1. **Только `train`.** Каждый синтетический пример обязан иметь
   `"split": "train"`. Ручной `val`/`test` не пополняется и не меняется.
2. **Проверка ядром.** Генератор вызывает `compile_morpheme_analysis` и
   принимает запрос только если целевой кластер реально присутствует в
   trie-разборе. Для чистых примеров запрещены другие профильные биты; для
   трудных пар целевой кластер должен доминировать по поддержке.
3. **Детерминизм.** Генератор использует фиксированный seed и не обращается
   к сети; один и тот же запуск даёт тот же файл.
4. **Провенанс.** Поле `"source": "synthetic-v1"`, поле `family` описывает
   шаблон, `language` — `ru`/`en`. Трудные пары дополнительно помечаются
   `notes`.
5. **Баланс.** 500 примеров на класс, 250 RU / 250 EN, доля трудных пар
   ограничена ~10% на язык, чтобы они не вытеснили чистые темы.
6. **Синтетика не исправляет метки.** Если ручной пример размечен по
   доминирующей теме, синтетика не может «переучить» его в другой класс:
   ручные `val`/`test` остаются независимым якорем.

## Формат примера

```json
{
  "query": "топология ориентированного графа и циклы",
  "label": 0,
  "cluster": "GRAPH",
  "split": "train",
  "source": "manual-v1"
}
```

`cluster` должен совпадать с `labels[label]`; `merge_corpora.py` проверяет
это и восстанавливает поле, если оно пропущено.

## Рабочий цикл

```bash
# 1. добавить примеры в text_clusters_manual.json

# 2. проверить схему и собрать объединённый корпус
python3 tests/test_corpus.py
python3 tools/merge_corpora.py \
  training/corpora/text_clusters.json \
  training/corpora/text_clusters_manual.json \
  training/corpora/text_clusters_manual_v2.json \
  -o training/corpora/text_clusters_expanded.json

# 3. извлечь признаки из алгоритмов ядра
python3 -m training.ae_features \
  training/corpora/text_clusters_expanded.json \
  data/text_clusters_expanded_features.json

# 4. обучить и оценить
python3 -m training.ae_graph_train data/text_clusters_expanded_features.json \
  --epochs 300 --hidden-dim 0 --learning-rate 0.01 --weight-decay 0.01 \
  --patience 60 --checkpoint checkpoints/text_clusters_expanded.json
python3 -m training.ae_graph_train data/text_clusters_expanded_features.json \
  --cv 5 --epochs 300 --hidden-dim 0 --learning-rate 0.01 --weight-decay 0.01
```

`tests/test_corpus.py` проверяет: диапазон меток, соответствие
`cluster`/`labels`, допустимые split'ы, отсутствие дубликатов, наличие
`train` и held-out примеров у каждого класса и актуальность объединённого
файла.

## Текущее состояние (seed + manual-v1 + manual-v2 + synthetic-v1)

- 4 950 запросов: 450 ручных/seed (9 классов × 50) + 4 500 синтетических
  (9 классов × 500, 250 RU / 250 EN на класс);
- split: 4 770 `train` / 90 `val` / 90 `test`; ручной якорь — по 10 `val` и
  10 `test` на класс, вся синтетика в `train`;
- 52 трудных ручных примера с `notes` + 393 синтетические трудные пары;
- default feature groups: `cluster_core, cluster_counts_core`
  (9 битов + 9 счётчиков = 18 признаков). Полный вектор ядра — 96 значений.

Метрики на ручном якоре (линейный режим, `hidden-dim 0`, `400` эпох):

| Метрика | Seed (90) | Ручной v2 (450) | + синтетика (4 950) |
|---|---:|---:|---:|
| Hold-out test accuracy | 0.667 (18) | 0.833 (90) | **0.931 ± 0.023** (90) |
| Hold-out test macro-F1 | 0.663 | 0.835 | — |
| 5-fold CV accuracy, ручной якорь | 0.856 ± 0.125 | 0.809 ± 0.039 | **0.868 ± 0.014** |
| 5-fold CV macro-F1, ручной якорь | 0.844 ± 0.141 | 0.808 ± 0.037 | **0.867 ± 0.014** |
| 5-fold CV accuracy, полный корпус | — | — | **0.968 ± 0.002** |

Hold-out на ручном якоре (`val` + `test`, 180 примеров) — **0.898 ± 0.013**
(среднее по 5 seed). Разбивка:

| Подмножество | Примеров | Accuracy |
|---|---:|---:|
| Однозначные (один кластерный бит) | 121 | **0.944 ± 0.004** |
| Трудные (два и более бита) | 59 | **0.813 ± 0.042** |
| RU | 81 | 0.849 ± 0.009 |
| EN | 99 | 0.937 ± 0.021 |

Трудные пары выросли с `0.500` до `0.813`: счётчики кластеров сохраняют
поддержку темы, а слой составных терминов разрешает часть конфликтов
(`neural network`, `routing table`, `network flow`). Остаточные ошибки —
неизвестные контексты, а не отдельные корни. Это ограничение представления:
следующий шаг — синтаксические признаки, а не бесконечное расширение
таблицы фраз.

Типичные оставшиеся ошибки:

- `GRAPH/NET`: `graph traversal and connected components` → `NET`
  (корень `connect` даёт бит сети);
- `TEXT/KNOW`: `knowledge text and grammar` → `KNOW`
  (оба кластера присутствуют, `KNOW` чаще в обучении);
- `NUM/GRAPH`: `algebraic graph theory and spectrum` → `GRAPH`
  (`graph` перевешивает `spectrum`);
- `ACTION/COMPUTE`: `refactor module and update dependency` → `COMPUTE`
  (`module` и `dependency` дают два бита против одного `refactor`).

Это не повод менять метки: запросы размечены по доминирующей теме и
помечены `notes`. Следующая волна должна либо расширить словарь trie, либо
добавить контекстные признаки, а не переобучаться на синтетических метках.

### Сравнение ёмкости модели

5-fold CV на ручном якоре (450), `400` эпох, `lr=0.01`, `wd=0.01`,
среднее по 5 seed:

| Режим | CV accuracy | CV macro-F1 |
|---|---:|---:|
| `--hidden-dim 0` (линейный) | 0.868 ± 0.014 | 0.867 ± 0.014 |
| `--hidden-dim 8` | **0.881 ± 0.007** | **0.880 ± 0.008** |
| `--hidden-dim 16` | 0.874 ± 0.007 | 0.873 ± 0.008 |

`hidden-dim 8` немного лучше на ручном якоре, но разница около `1.3 pp`
близка к шуму, а основные hold-out замеры сделаны в линейном режиме.
Линейный остаётся default; `hidden-dim 8` стоит перепроверить на следующей
ручной волне, а не выбирать по одному CV.

## Следующие шаги

1. Расширить словарь trie для `NET`/`GRAPH`: `network`, `routing` и
   родственные корни должны давать бит `NET`, а не только `GRAPH`/`FLOW`.
2. Собрать новую ручную волну (фокус на трудных парах) и проверить, что
   синтетика не подменила ручной якорь: метрики на `val`/`test` должны
   остаться сопоставимыми.
3. Проверить согласованность разметки вторым проходом (inter-annotator
   agreement) на случайной подвыборке, отдельно по трудным парам.
4. Сравнить модели: линейный режим, `hidden-dim 8/16`, class weights;
   фиксировать не только accuracy, но и accuracy на `easy`/`hard`.
5. Пересчитать метрики и обновить таблицу; хранить отчёт в `reports/`
   (каталог не коммитится).
